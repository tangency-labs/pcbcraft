# #303 failure-path review

The separate pass followed Rules entry points through source-view capture, class
validation and command dispatch, session history, original-view refresh and live
MCP refusal. It also followed schematic endpoint projection and accepted PCB
memberships into the current sparse net graph. No worker, queue, transport,
persistent cache or saved rule vocabulary is introduced.

Class text and assignment sets belong to a disposable modal snapshot. The original
view ID, target, epoch and session revision gate every save; changing focus alone
does not grant another view authority. Target changes disable publication, and
closing the original detached view expires the form. Cancel/backdrop/close use the
existing Craft modal dismissal and emit no command. Navigation that could replace
a changed draft is disabled. Board-default transitions retain the captured source
rather than binding whichever editor currently owns focus. These paths are covered
by real-control stale-target/revision, cancel, detached-close and board-default tests.

Create/update and complete-set assignment use the existing engine commands with
expected revisions. Those commands validate before one session change; failure
keeps the draft/error and cannot publish partial definitions or bindings. Fields
preserve exact untouched integers and parse edited strings through shared units;
the draft delegates sparse business validation to the engine. Tests cover invalid
text, mixed units, rename precision, one-step Undo/Redo, class assignment/history,
Update PCB, split views and production native codecs. GUI writes are inspectable
through the existing class/assignment contracts and reach PCB contact policy.
The live editor's ordinary project-modal refusal is exercised with a class command.

Selection is read-only and runs when Rules opens, rather than in ordinary paint or
pointer frames. Missing endpoints fail; free/bare groups supply no target. The PCB
helper uses full contact-island membership, then current typed logical authority.
A focused regression found that a pad's own intended membership alone hid a
conflicting island; the helper now combines the island's memberships. Another found
that omitted bare terminals could hide a pending accepted split; accepted terminals
now remain in ambiguity evidence. Both regressions pass, along with exact unchanged
snapshot/history/bytes tests. Equal names never select a winner.

Review by reading also covered missing project/view during refresh, optional board
inheritance, unknown classes, command failures and shared-modal keyboard dismissal.
New rendered UI is checked separately in native GPU readback and packaged headless
Chrome. Those checks establish produced pixels/control behavior, without native
window/compositor latency, Wayland endurance or repeated-instance/board-transfer
qualification. The retained render helper remains outside production dependencies.

Packaged browser resize exposed an Area positioning frame that remained visible
until new input. The shared settings-form adapter now schedules one settling paint
only when viewport bounds/scale change. A regression checks the repaint request
and centered bounds; packaged resize is rechecked without pointer movement. The
cache key includes viewport identity, and stable metrics do not schedule an idle
repaint loop. This changes shared form presentation, so app/chrome checks are
repeated; unchanged engine and evidence-validator results remain applicable.
