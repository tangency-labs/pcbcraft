# Via displacement and connected segment dragging (#248)

The saved track-only replay is the baseline for the two new routing gestures.
It ran on upstream main at `b76694d757e9d3b2df7c838219bab02186e50814`
with Rust 1.100.0, the workspace CI profile and locked dependencies, on an Apple
M5 Max running macOS 27.2.1. The single, cascade and branch cases reached their
endpoints with one, two and one track replacements respectively. The locked
obstacle blocked the route. [Raw samples and environment](tracks-before.json)

The baseline took three samples per case. The first case of each iteration
includes the cost of preparing a fresh session's planning geometry. The timings
measure native service costs on a shared host. Candidate measurements are pending.

## Replaying on the candidate

Use the native `board_perf` example with the `performance-harness` feature in
the same CI profile. From this directory, set `after_perf` to the binary's
absolute path and `revision` to its full source commit. Save the actual host and
compiler metadata in `environment`, using the baseline report's
`environment` object as the template. Set its revision to the candidate commit.

```sh
out=$(mktemp -d)
gzip -dc tracks-fixture.json.gz > "$out/tracks.json"
"$after_perf" shove "$out/tracks.json" "$environment" 3 "$out/tracks-after.json"
"$after_perf" shove_joint_fixture "$out/tracks.json" "$revision" "$out/joints.json"
"$after_perf" shove "$out/joints.json" "$environment" 3 "$out/joints-after.json"
```

Use the exact [saved track fixture](tracks-fixture.json.gz) for the matched
comparison. Its uncompressed SHA-256 is
`83608fa0220b318af2b890a75add337a979a35cd66cf35854fd1c77354a2fedc`.
The joint fixture generator adds a through via and connected tracks using the
board commands. Keep the generated bytes with the candidate report because
generation assigns fresh object IDs.

The via case checks the published center and the width, layer and fixed end of
both followers. The drag case checks the shared endpoint and compares the
previewed rail with committed copper. Both cases require one publication,
exhaustive clearance on changed copper, exact Undo/Redo and native reopen.
Planning and preparation advance in batches of 256. Publication timing begins
after validation. History and exhaustive checks run outside the timed region.
